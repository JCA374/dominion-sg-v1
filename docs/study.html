Study this project

For someone who wants to learn from this project rather than follow it: what to read in which order, the ideas you need, the words we use, how to run it yourself, and a few exercises.

Reading order

  1. Overview (5 min): the question, the four steps, the diagram.
  2. The data (10 min): what one label is, what "verified" means, the splits and what a player can know.
  3. Results (10 min): the ablation table first, then each step as it finishes.
  4. The model (5 min): the network and the two losses (pairwise + anchors, then PPO).
  5. Training and Log: the PPO curves of A and B, and every decision with its reason.
  6. Code: bv-v1/c/bv.c (bv_grade, bv_validate, bv_decide_main: the teacher), supervise.py (the supervised step), rl-v3/train.py (ppo_update, make_games), ablation.py and pipeline.py (the experiment's order and rules).

Key concepts

Paired rollouts

Every candidate is played out on the same hidden-card draws, so the comparison removes the luck of the draw: the difference between two candidates has a much smaller variance than either value. Shows up in bv_grade (bv.c) and in every SE on the Results tab. Common mistake: comparing unpaired means and calling 52% vs 50% a difference.

Verified improvement

The best graded candidate is re-tested against c2's choice on fresh, independent draws before it is taught. Picking the maximum of six noisy estimates flatters the winner (winner's curse); the validation removes that bias. Shows up as VG / VSE in the labels. Common mistake: training on the raw argmax of noisy grades.

Anchors (KL regularisation)

The supervised loss alone would move c2 everywhere; the KL to frozen c2 on 85,000 of its own positions holds it in place except where a label pulls. Shows up in supervise.py and as "anchor KL" and "argmax agreement" on Results. Common mistake: anchoring only on the labelled decision kind, letting routine subdecisions (discards, trashing) drift.

The PPO ratio and the temperature

PPO compares the new policy's probability of a sampled move with the probability the sampler used. If the sampler divided logits by a temperature and the update did not, every ratio is wrong from the first step (3.6% were already outside the clip band at temperature 0.7). Shows up in rl-v3/train.py policy_logp and its test. Common mistake: checking the ratio only at temperature 1, where the bug is invisible.

Matched control

Branch A gets exactly what B gets except the supervised step: the same start, settings, game budget and, per seed, the same kingdoms and opponents at every iteration. Otherwise a difference could come from the stream. Common mistake: comparing a new branch with an old run trained under other settings.

Frozen manifests and exclusions

The games every comparison is played on are written once, before any game, and no kingdom of them is ever trained or labelled on. Shows up in manifests/ and the match manifests (source and library hashes). Common mistake: tuning on the test kingdoms, or resuming a match with different settings.

Simulator view vs public view

The teacher deals the cards a player cannot see; the original sampler kept the opponent's discard pile exactly, which a player never knows. Shows up in docs/observation.md and survive.py. Common mistake: a teacher that wins partly by peeking.

Reproduce it

git clone --recursive https://github.com/JCA374/dominion-sg-v1 && cd dominion-sg-v1
# Python: a venv with numpy and torch (CPU), e.g. the rl-v3 one: python -m venv .venv && .venv/bin/pip install numpy torch
.venv/bin/python -m pytest -q rl-v3/tests          # 27 tests, ~15 s (C builds on first use)
(cd bv-v1 && ../.venv/bin/python -m pytest -q tests)   # 22 tests, ~2 min
.venv/bin/python ablation.py --arms mirror,buy --workers 7    # mirror ~1 min, buy teacher ~45 min on 4 cores
.venv/bin/python ablation_report.py                  # results/ablation.json
.venv/bin/python anchors.py --games 600 --name a1    # 85k positions, ~2 min

Run on a 4-core laptop CPU. The pilot (20,000 labels) takes a few hours, each PPO run of 100 iterations about 1.5 hours.

Exercises

  1. See the temperature bug. In rl-v3/train.py make policy_logp ignore temp, run pytest rl-v3/tests/test_ppo_fixes.py -k ratio. Expect the mean ratio error at temperature 0.7 to jump from ~1e-7 to ~0.05.
  2. Peek or not. Run survive.py after the pilot and compare "simulator" and "public": how many of the teacher's overrides need the opponent's discard pile?
  3. Fewer draws. Run the buy arm with --k0 16 --k1 16 (ablation.py's SETTINGS) on the same manifest and compare with the 32-draw arm pair by pair. Expect more overrides and a lower score: noise overrides.
  4. Anchor strength. Run supervise.py with --lam 0.1 and --lam 10: plot held-out pair accuracy against anchor KL. Where does a dev match (netmatch.py) peak?
